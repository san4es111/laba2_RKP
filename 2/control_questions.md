# Ответы на контрольные вопросы

## Система контроля версий

1. Коммит — сохранённое состояние файлов проекта с автором, датой и сообщением.
2. Если создать один коммит в конце, промежуточные этапы и история разработки не сохранятся.
3. Локальный репозиторий находится на компьютере, удалённый — на сервере. Команда `git push` отправляет коммиты на сервер.
4. `.gitignore` исключает временные и служебные файлы. Если добавить виртуальное окружение или служебные каталоги, репозиторий станет тяжёлым и засорённым, возможны конфликты настроек.
5. История: `git log`. Содержимое коммита: `git show <хеш>`.

## По разработанному приложению

1. Ненулевой код возвращается, например, в строке `return 1` после ошибки. Если его убрать, система может принять ошибочное завершение за успешное.
2. Выход за диапазон — обычное проверяемое условие, а не ошибка выполнения Python, поэтому используется `if`.
3. `math.sqrt()` нельзя применять к отрицательному числу в области действительных чисел. Если вычислить корень до проверки, возникнет `ValueError`.
4. При `A = 0` знаменатель формулы `2*A` равен нулю, поэтому возникнет деление на ноль; уравнение становится линейным.
5. Программа сравнивает список аргументов с `["--help"]`.
6. `sys.argv[0]` содержит имя запущенного файла. Остальные элементы — переданные параметры, поэтому их число равно `len(sys.argv) - 1`.
7. Коэффициенты вводятся с клавиатуры или передаются в командной строке. Клавиатура удобна для ручной работы, параметры — для быстрого повторения и автоматического тестирования.

## Ввод данных и типы

1. `x = input(...); print(x + 1)` вызовет `TypeError`, потому что `x` — строка, а `1` — число.
2. При вводе `5` выражение `x * 3` выведет `555`.
3. `input()` всегда возвращает `str`, независимо от введённых символов.
4. `int()` преобразует строку в целое число. Без него арифметика выполняться не будет или даст строковый результат.
5. `int("abc")` вызывает `ValueError`; приложение перехватывает его через `except ValueError`.
6. В `try` выполняются потенциально ошибочные операции. Если возникает указанное исключение, выполнение переходит в `except`; если нет — `except` пропускается.
7. `{x:.3f}` выводит вещественное число с тремя знаками после запятой и округлением.
8. `int()` успешно обработает `"5"`, `" 5 "`, `"+5"`. Строки `"5.5"`, `"5,5"` и пустая строка вызовут `ValueError`; приложение выведет сообщение об ошибке и завершится с кодом 1.

## Потоки вывода и код возврата

1. `stdout` предназначен для обычных результатов, `stderr` — для ошибок. Разделение позволяет перенаправлять их независимо.
2. При `python mathtool.py solve > result.txt` обычный вывод попадёт в файл, а ошибка о букве останется на экране, поскольку выводится в `stderr`.
3. Код возврата сообщает системе итог работы. Ноль означает успех, ненулевое значение — ошибку.
4. Код возврата нужен скриптам, оболочке и системам тестирования для автоматического определения результата.

## Значения выражений

1. `7 / 2 = 3.5`; `7 // 2 = 3`; `7 % 2 = 1`.
2. `9 // 6 + 9 / 6 = 1 + 1.5 = 2.5`.
3. `5 + 7 // abs(9 - 11) * 3 = 5 + 7 // 2 * 3 = 14`.
4. Результат — `True`: левая часть `5 // 2 == 2` истинна, поэтому всё выражение с `or` истинно.

## Результат фрагмента

Условие `A + B <= 40` ложно: `17 + 25 = 42`. Условие `B % 5 != 0` тоже ложно. Выполняется `else`:

- `A = 6 + 25 = 31`;
- `B = 25 - 31 = -6`.

Вывод: `31 -6`.

## Является ли ситуация исключительной

- `A = 0` — нет, это проверяемый случай линейного уравнения;
- коэффициент `50000` — нет, значение корректного типа, но не проходит ограничение;
- буква вместо коэффициента — да, `int()` вызывает `ValueError`;
- отрицательный дискриминант — нет, это нормальный случай без действительных корней;
- неизвестная команда — нет, это ошибка входных данных, проверяемая условием.
